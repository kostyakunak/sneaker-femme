# 🔍 Диагностика проблемы подключения к БД

## ✅ Что уже есть

Из скриншота видно, что переменные установлены:
- ✅ `DB_HOST`
- ✅ `DB_NAME`
- ✅ `DB_PASSWORD`
- ✅ `DB_PORT`
- ✅ `DB_SSLMODE`
- ✅ `DB_USER`
- ✅ `NODE_ENV`

## ❌ Проблема: ECONNREFUSED

Ошибка `ECONNREFUSED` означает, что приложение не может подключиться к PostgreSQL.

## 🔍 Возможные причины и решения

### 1. Переменные не связаны с PostgreSQL сервисом

**Проблема:** Переменные установлены вручную, но не используют значения из PostgreSQL сервиса.

**Решение:**
1. Откройте сервис **PostgreSQL** (не приложение)
2. Перейдите в **Variables**
3. Найдите переменные `PGHOST`, `PGPORT`, `PGDATABASE`, `PGUSER`, `PGPASSWORD`
4. Скопируйте их значения
5. Вернитесь к сервису **sneaker-femme** → **Variables**
6. Обновите переменные `DB_*` скопированными значениями

**Или используйте ссылки:**
Вместо копирования значений, можно использовать ссылки на переменные PostgreSQL:
- `DB_HOST` = `${PGHOST}`
- `DB_PORT` = `${PGPORT}`
- `DB_NAME` = `${PGDATABASE}`
- `DB_USER` = `${PGUSER}`
- `DB_PASSWORD` = `${PGPASSWORD}`

### 2. PostgreSQL сервис не запущен

**Проверка:**
1. Откройте сервис **Postgres** в Railway
2. Убедитесь, что статус показывает **"Running"** (зеленая галочка)
3. Если не запущен - запустите вручную

### 3. Неправильные значения переменных

**Проверка:**
1. Откройте сервис **Postgres** → **Variables**
2. Проверьте значения `PGHOST`, `PGPORT`, `PGDATABASE`, `PGUSER`, `PGPASSWORD`
3. Убедитесь, что в сервисе **sneaker-femme** переменные `DB_*` имеют **точно такие же значения**

### 4. Проблема с SSL

**Проверка:**
- Убедитесь, что `DB_SSLMODE=require` (не `required`, не `enable`, именно `require`)

### 5. Переменные не применены

**Решение:**
1. После изменения переменных, Railway должен автоматически перезапустить сервис
2. Если не перезапустился - нажмите **"Redeploy"** вручную
3. Или перезапустите сервис через кнопку в настройках

## 🎯 Быстрая проверка

### Шаг 1: Проверьте значения в PostgreSQL сервисе

1. Откройте сервис **Postgres**
2. Variables → нажмите на значок "глаз" рядом с `PGHOST`
3. Запомните значение (например: `monorail.proxy.rlwy.net`)

### Шаг 2: Проверьте значения в приложении

1. Откройте сервис **sneaker-femme**
2. Variables → нажмите на значок "глаз" рядом с `DB_HOST`
3. Значение должно быть **точно таким же**, как `PGHOST`

### Шаг 3: Повторите для всех переменных

- `DB_HOST` = `PGHOST`
- `DB_PORT` = `PGPORT`
- `DB_NAME` = `PGDATABASE`
- `DB_USER` = `PGUSER`
- `DB_PASSWORD` = `PGPASSWORD`

## 🔧 Альтернативное решение: Использовать ссылки

Вместо копирования значений, можно использовать ссылки на переменные PostgreSQL:

1. В сервисе **sneaker-femme** → **Variables**
2. Для каждой переменной `DB_*` используйте синтаксис `${PG*}`:
   - `DB_HOST` = `${PGHOST}`
   - `DB_PORT` = `${PGPORT}`
   - `DB_NAME` = `${PGDATABASE}`
   - `DB_USER` = `${PGUSER}`
   - `DB_PASSWORD` = `${PGPASSWORD}`

**Важно:** Railway должен автоматически разрешать эти ссылки, но если не работает - используйте копирование значений.

## 📋 Чек-лист проверки

- [ ] PostgreSQL сервис запущен (зеленая галочка)
- [ ] `DB_HOST` = значение из `PGHOST` (точно такое же)
- [ ] `DB_PORT` = значение из `PGPORT` (точно такое же)
- [ ] `DB_NAME` = значение из `PGDATABASE` (точно такое же)
- [ ] `DB_USER` = значение из `PGUSER` (точно такое же)
- [ ] `DB_PASSWORD` = значение из `PGPASSWORD` (точно такое же)
- [ ] `DB_SSLMODE` = `require` (не `required`, не другое)
- [ ] `NODE_ENV` = `production`
- [ ] Приложение перезапущено после изменения переменных
- [ ] Проверены логи - нет ошибок подключения

## 🆘 Если все еще не работает

1. **Проверьте логи PostgreSQL сервиса** - возможно, там есть ошибки
2. **Проверьте, что оба сервиса в одном проекте** - они должны быть связаны
3. **Попробуйте пересоздать переменные** - удалите и создайте заново
4. **Проверьте сетевые настройки** - убедитесь, что сервисы могут общаться друг с другом
