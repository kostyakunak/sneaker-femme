# Руководство по развертыванию на Railway

## Архитектура приложения

EverShop - это **SSR (Server-Side Rendering)** приложение на базе Express + React + PostgreSQL. Это означает, что фронтенд и бэкенд неразделимы - они работают как единое приложение.

## ⚠️ Важное замечание о Netlify

Поскольку EverShop использует SSR, **разделение на фронтенд (Netlify) и бэкенд (Railway) невозможно без серьезной переработки архитектуры**. Приложение рендерит страницы на сервере, а не генерирует статические файлы.

### Рекомендуемое решение: Все на Railway

Разверните все приложение на Railway - это самый простой и правильный подход для SSR приложений.

## Структура репозиториев

### Вариант 1: Один репозиторий (рекомендуется)

```
solovey/
└── evershop-dev/          # Основной репозиторий
    ├── packages/          # Пакеты приложения
    ├── extensions/        # Расширения
    ├── config/            # Конфигурация
    ├── Dockerfile         # Docker образ
    ├── railway.json       # Конфигурация Railway
    └── .env.example       # Пример переменных окружения
```

**Что выгружать в Git:**
- Весь каталог `evershop-dev/`
- Исключить: `node_modules/`, `.evershop/`, `.env`, `media/`, `public/` (если они генерируются)

### Вариант 2: Разделение (если действительно нужно)

Если вы все же хотите разделить (требует переработки):
1. **Backend репозиторий** - API сервер на Railway
2. **Frontend репозиторий** - Статический фронтенд на Netlify (потребует создания нового фронтенда)

⚠️ **Это потребует значительной переработки кода!**

## Развертывание на Railway

### Шаг 1: Подготовка репозитория

1. Убедитесь, что `.gitignore` правильно настроен:
   ```bash
   node_modules/
   .env
   .evershop/
   dist/
   media/
   public/
   ```

2. Инициализируйте Git репозиторий (если еще не сделано):
   ```bash
   cd evershop-dev
   git init
   git add .
   git commit -m "Initial commit"
   ```

3. Создайте репозиторий на GitHub/GitLab и запушьте код:
   ```bash
   git remote add origin <your-repo-url>
   git push -u origin main
   ```

### Шаг 2: Создание проекта на Railway

1. Зайдите на [railway.app](https://railway.app)
2. Создайте новый проект
3. Выберите "Deploy from GitHub repo"
4. Подключите ваш репозиторий

### Шаг 3: Настройка PostgreSQL

1. В проекте Railway нажмите "+ New"
2. Выберите "Database" → "Add PostgreSQL"
3. Railway автоматически создаст переменные окружения:
   - `PGHOST`
   - `PGPORT`
   - `PGDATABASE`
   - `PGUSER`
   - `PGPASSWORD`

### Шаг 4: Настройка переменных окружения

В настройках сервиса приложения добавьте переменные окружения:

**Обязательные (Railway автоматически создаст для PostgreSQL):**
- `DB_HOST` → Используйте `${PGHOST}` или создайте переменную с тем же значением
- `DB_PORT` → Используйте `${PGPORT}` или создайте переменную
- `DB_NAME` → Используйте `${PGDATABASE}` или создайте переменную
- `DB_USER` → Используйте `${PGUSER}` или создайте переменную
- `DB_PASSWORD` → Используйте `${PGPASSWORD}` или создайте переменную

**Рекомендуемые:**
- `DB_SSLMODE=require` (для безопасного подключения к PostgreSQL)
- `NODE_ENV=production`
- `PORT` (Railway автоматически устанавливает, но можно указать явно)

**Опциональные (в зависимости от используемых расширений):**
- `AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY`, `AWS_REGION`, `AWS_BUCKET_NAME` (для S3)
- `AZURE_STORAGE_CONNECTION_STRING`, `AZURE_STORAGE_CONTAINER_NAME` (для Azure)
- `RESEND_API_KEY` (для Resend email)
- `SENDGRID_API_KEY` (для SendGrid email)
- `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET` (для Google Login)

### Шаг 5: Настройка сборки

Railway автоматически обнаружит `Dockerfile` и `railway.json`. Убедитесь, что:

1. **Dockerfile** находится в корне проекта
2. **railway.json** настроен правильно
3. Build command: Railway использует Dockerfile, поэтому сборка происходит автоматически

### Шаг 6: Первый запуск и миграции

При первом запуске приложение автоматически:
1. Установит зависимости (`npm install`)
2. Соберет проект (`npm run build`)
3. Запустит миграции базы данных (при первом запуске)

### Шаг 7: Настройка домена

1. В настройках сервиса перейдите в "Settings" → "Networking"
2. Нажмите "Generate Domain" для получения бесплатного домена
3. Или добавьте свой кастомный домен

## Проверка развертывания

После развертывания проверьте:

1. **Логи Railway**: Убедитесь, что нет ошибок при запуске
2. **База данных**: Проверьте подключение к PostgreSQL
3. **Приложение**: Откройте домен и проверьте работу сайта
4. **Админ-панель**: Попробуйте зайти в `/admin` (если настроено)

## Мониторинг и логи

- **Логи**: Railway показывает логи в реальном времени в панели управления
- **Метрики**: Railway предоставляет метрики использования ресурсов
- **Алерты**: Настройте уведомления о проблемах

## Резервное копирование

1. **База данных**: Railway автоматически делает бэкапы PostgreSQL
2. **Код**: Храните код в Git репозитории
3. **Медиа файлы**: Если используете локальное хранилище, настройте S3/Azure для production

## Обновление приложения

1. Внесите изменения в код
2. Закоммитьте и запушьте в Git:
   ```bash
   git add .
   git commit -m "Update application"
   git push
   ```
3. Railway автоматически обнаружит изменения и пересоберет приложение

## Troubleshooting

### Проблема: Приложение не запускается

**Решение:**
- Проверьте логи в Railway
- Убедитесь, что все переменные окружения установлены
- Проверьте подключение к базе данных

### Проблема: Ошибки подключения к БД

**Решение:**
- Убедитесь, что PostgreSQL сервис запущен
- Проверьте переменные окружения `DB_*`
- Убедитесь, что `DB_SSLMODE=require` установлен

### Проблема: Медленная сборка

**Решение:**
- Используйте `.dockerignore` для исключения ненужных файлов
- Рассмотрите использование кэша Docker слоев
