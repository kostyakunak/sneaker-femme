# 🔗 Настройка GitHub → Railway: Подробная инструкция

## Что происходит автоматически

Railway автоматически:
- ✅ Обнаруживает `railway.json` и `Dockerfile`
- ✅ Настраивает автоматическое развертывание при каждом push
- ✅ Собирает Docker образ
- ✅ Запускает приложение

## 📋 Пошаговая настройка в интерфейсе Railway

### Шаг 1: Подключение GitHub репозитория

1. **Зайдите на [railway.app](https://railway.app)**
2. **Войдите через GitHub** (если еще не вошли)
3. **Нажмите "New Project"**
4. **Выберите "Deploy from GitHub repo"**
5. **Выберите репозиторий `sneaker-femme`**
6. Railway автоматически:
   - Подключит репозиторий
   - Начнет первую сборку
   - Создаст сервис приложения

### Шаг 2: Настройки сервиса приложения

После подключения репозитория, откройте созданный сервис и проверьте настройки:

#### 2.1. Вкладка "Settings" → "Source"

**Что проверить:**
- ✅ **Repository**: `kostyakunak/sneaker-femme`
- ✅ **Branch**: `main` (или ваша рабочая ветка)
- ✅ **Root Directory**: оставьте пустым (или `/` если нужно)
- ✅ **Auto Deploy**: должен быть включен ✅

**Что это значит:**
- При каждом `git push` в ветку `main`, Railway автоматически пересоберет и перезапустит приложение

#### 2.2. Вкладка "Settings" → "Build & Deploy"

**Что проверить:**

1. **Build Command**: 
   - Railway использует Dockerfile, поэтому команда сборки не нужна
   - Оставьте пустым или удалите, если там что-то есть

2. **Start Command**:
   - Должно быть: `npm run start`
   - Или Railway возьмет из `railway.json` (там уже указано)

3. **Dockerfile Path**:
   - Должно быть: `Dockerfile`
   - Railway автоматически найдет его в корне

4. **Watch Paths**:
   - Оставьте пустым (Railway отслеживает весь репозиторий)

#### 2.3. Вкладка "Settings" → "Networking"

**Настройка порта:**
- Railway автоматически определяет порт из переменной `PORT`
- По умолчанию: `3000`
- Можно оставить как есть

**Настройка домена:**
1. Нажмите "Generate Domain"
2. Railway создаст домен вида: `your-app-name.up.railway.app`
3. Или добавьте свой кастомный домен

#### 2.4. Вкладка "Variables"

**Здесь нужно добавить переменные окружения** (см. Шаг 4 ниже)

### Шаг 3: Создание PostgreSQL сервиса

1. **В проекте Railway нажмите "+ New"**
2. **Выберите "Database" → "Add PostgreSQL"**
3. Railway автоматически:
   - Создаст PostgreSQL базу данных
   - Создаст переменные окружения `PG*`
   - Настроит подключение

**Важно:** PostgreSQL сервис создаст свои переменные:
- `PGHOST`
- `PGPORT`
- `PGDATABASE`
- `PGUSER`
- `PGPASSWORD`

### Шаг 4: Настройка переменных окружения

#### 4.1. Откройте PostgreSQL сервис → "Variables"

Скопируйте значения этих переменных:
- `PGHOST`
- `PGPORT`
- `PGDATABASE`
- `PGUSER`
- `PGPASSWORD`

#### 4.2. Откройте сервис приложения → "Variables"

Добавьте следующие переменные:

| Переменная | Значение | Откуда взять |
|------------|----------|--------------|
| `DB_HOST` | Скопируйте значение `PGHOST` | Из PostgreSQL сервиса |
| `DB_PORT` | Скопируйте значение `PGPORT` | Из PostgreSQL сервиса |
| `DB_NAME` | Скопируйте значение `PGDATABASE` | Из PostgreSQL сервиса |
| `DB_USER` | Скопируйте значение `PGUSER` | Из PostgreSQL сервиса |
| `DB_PASSWORD` | Скопируйте значение `PGPASSWORD` | Из PostgreSQL сервиса |
| `DB_SSLMODE` | `require` | Введите вручную |
| `NODE_ENV` | `production` | Введите вручную |
| `PORT` | `3000` | Опционально (Railway установит автоматически) |

**Как добавить переменную:**
1. Нажмите "+ New Variable"
2. Введите имя переменной (например, `DB_HOST`)
3. Введите значение (скопированное из PostgreSQL)
4. Нажмите "Add"

### Шаг 5: Проверка автоматического развертывания

#### 5.1. Как работает авто-деплой

После настройки:
1. Вы делаете изменения в коде
2. Делаете `git commit` и `git push`
3. Railway автоматически:
   - Обнаруживает изменения
   - Запускает новую сборку
   - Перезапускает приложение

#### 5.2. Проверка статуса развертывания

В интерфейсе Railway вы увидите:
- **"Deploying"** - идет сборка и развертывание
- **"Active"** - приложение работает
- **"Failed"** - ошибка (проверьте логи)

#### 5.3. Просмотр логов

1. Откройте сервис приложения
2. Перейдите во вкладку "Deployments"
3. Выберите последнее развертывание
4. Просмотрите логи сборки и запуска

### Шаг 6: Настройка веток (опционально)

Если хотите развертывать из другой ветки:

1. Settings → Source
2. Измените "Branch" на нужную ветку
3. Railway будет развертывать из этой ветки

**Рекомендация:** Используйте `main` для production

### Шаг 7: Настройка окружений (опционально)

Railway поддерживает разные окружения:

1. **Production** - основное развертывание
2. **Preview** - автоматические preview для pull requests

**Настройка Preview:**
1. Settings → Source
2. Включите "Preview Deployments"
3. Railway будет создавать preview для каждого PR

## 🔧 Дополнительные настройки

### Настройка ресурсов

1. Settings → Resources
2. Выберите план:
   - **Starter** - для начала (бесплатно)
   - **Developer** - для production ($5/месяц)
   - **Pro** - для больших нагрузок ($20/месяц)

### Настройка уведомлений

1. Settings → Notifications
2. Настройте уведомления о:
   - Успешных развертываниях
   - Ошибках развертывания
   - Проблемах с приложением

### Настройка мониторинга

Railway автоматически предоставляет:
- Метрики использования CPU/RAM
- Логи в реальном времени
- Историю развертываний

## 🆘 Решение проблем

### Проблема: Railway не видит изменения

**Решение:**
1. Проверьте, что Auto Deploy включен
2. Убедитесь, что вы пушите в правильную ветку
3. Проверьте настройки Source → Branch

### Проблема: Ошибка сборки

**Решение:**
1. Проверьте логи развертывания
2. Убедитесь, что `Dockerfile` в корне проекта
3. Проверьте, что `railway.json` корректен

### Проблема: Приложение не запускается

**Решение:**
1. Проверьте логи приложения
2. Убедитесь, что все переменные окружения установлены
3. Проверьте подключение к базе данных
