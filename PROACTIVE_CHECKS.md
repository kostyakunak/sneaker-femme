# 🛡️ Проактивная система проверок перед деплоем

## 🎯 Цель

Эта система позволяет **предугадывать проблемы до деплоя**, а не ждать ошибок из логов Railway.

## 📋 Что проверяется

### 1. Структура workspace пакетов
- ✅ Все необходимые пакеты существуют
- ✅ Все необходимые файлы на месте
- ✅ Конфигурационные файлы (.swcrc, tsconfig.json) присутствуют

### 2. Зависимости между пакетами
- ✅ Правильные зависимости в package.json
- ✅ Порядок компиляции соответствует зависимостям
- ✅ Нет циклических зависимостей

### 3. Скрипты компиляции
- ✅ Все необходимые скрипты существуют
- ✅ Порядок выполнения правильный
- ✅ Dockerfile использует правильный порядок

### 4. Необходимые файлы
- ✅ Dockerfile
- ✅ railway.json
- ✅ Все package.json файлы
- ✅ Конфигурационные файлы

### 5. Dockerfile
- ✅ Правильный порядок компиляции
- ✅ Все файлы копируются
- ✅ CMD/ENTRYPOINT присутствует

### 6. Конфигурация
- ✅ .swcrc файлы на месте
- ✅ tsconfig.json валиден
- ✅ .dockerignore настроен правильно

## 🚀 Использование

### Автоматическая проверка перед коммитом

```bash
# Запустить проверки
npm run pre-deploy-check

# Или напрямую
node scripts/pre-deploy-check.js
```

### Анализ зависимостей

```bash
# Проанализировать зависимости и порядок компиляции
node scripts/analyze-dependencies.js
```

### Добавить в package.json

```json
{
  "scripts": {
    "pre-deploy-check": "node scripts/pre-deploy-check.js",
    "analyze-deps": "node scripts/analyze-dependencies.js",
    "precommit": "npm run pre-deploy-check"
  }
}
```

## 📊 Категории проверок

### 🔴 Критические (блокируют деплой)
- Отсутствие необходимых пакетов
- Неправильный порядок компиляции
- Отсутствие критических файлов
- Ошибки в конфигурации

### 🟡 Предупреждения (рекомендуется исправить)
- Отсутствие .dockerignore
- Отсутствие документации
- Потенциальные проблемы с производительностью

## 🔍 Примеры проверок

### Проверка порядка компиляции

```javascript
// ✅ Правильно
RUN npm run compile:db && npm run compile && npm run build

// ❌ Неправильно
RUN npm run compile && npm run compile:db && npm run build
```

### Проверка зависимостей

```javascript
// ✅ Правильно: evershop зависит от postgres-query-builder
{
  "dependencies": {
    "@evershop/postgres-query-builder": "^2.0.1"
  }
}

// ❌ Неправильно: зависимость отсутствует
```

## 📝 Добавление новых проверок

Чтобы добавить новую проверку, откройте `scripts/pre-deploy-check.js` и добавьте новую функцию:

```javascript
function checkNewThing() {
  success('Проверка новой вещи...');
  
  // Ваша логика проверки
  if (somethingWrong) {
    error('Что-то не так');
  } else {
    success('Все хорошо');
  }
}

// Вызовите в main()
checkNewThing();
```

## 🎯 Преимущества

1. **Раннее обнаружение проблем** - находим ошибки до деплоя
2. **Экономия времени** - не нужно ждать деплоя и проверять логи
3. **Автоматизация** - можно добавить в CI/CD
4. **Документация** - явно видно, что проверяется

## 🔄 Интеграция с Git Hooks

Можно добавить проверку в pre-commit hook:

```bash
# .husky/pre-commit
#!/bin/sh
npm run pre-deploy-check
```

Или использовать husky:

```json
{
  "husky": {
    "hooks": {
      "pre-commit": "npm run pre-deploy-check"
    }
  }
}
```

## 📚 Связанные документы

- `DEPLOY_CHECKLIST.md` - Чек-лист перед деплоем
- `CRITICAL_FIX.md` - Описание критических исправлений
- `ALL_FIXES_SUMMARY.md` - Полный список исправлений

## ⚠️ Важно

Эти проверки **не заменяют** тестирование и проверку логов, но **дополняют** их, позволяя находить проблемы на раннем этапе.
