# 🚀 Руководство по развертыванию на Railway

## ⚠️ Важное замечание об архитектуре

Это приложение использует **SSR (Server-Side Rendering)** - фронтенд и бэкенд работают как единое целое. React компоненты рендерятся на сервере, а не генерируются как статические файлы.

**Это означает:**
- ❌ **Невозможно** разделить на Netlify (фронт) и Railway (бэкенд) без серьезной переработки архитектуры
- ✅ **Рекомендуется** развернуть всё на Railway - это правильный подход для SSR приложений
- ⚠️ Если очень нужно использовать Netlify, можно настроить его как прокси к Railway API, но это избыточно и усложняет архитектуру

## 📦 Структура репозитория

### Один репозиторий (рекомендуется)

```
evershop-dev/
├── packages/          # Пакеты приложения
├── extensions/        # Расширения
├── config/            # Конфигурация
├── translations/      # Переводы
├── Dockerfile         # Docker образ для Railway
├── railway.json       # Конфигурация Railway
├── .env.example       # Пример переменных окружения
```

**Что выгружать в Git:**
- ✅ Весь каталог `evershop-dev/`
- ❌ Исключить: `node_modules/`, `.evershop/`, `.env`, `media/`, `public/` (если генерируются)

## 🚂 Шаг 2: Создание проекта на Railway

### 2.1. Регистрация/Вход

1. Перейдите на [railway.app](https://railway.app)
2. Войдите через GitHub (рекомендуется для автоматического деплоя)

### 2.2. Создание нового проекта

1. Нажмите **"New Project"**
2. Выберите **"Deploy from GitHub repo"**
3. Выберите ваш репозиторий
4. Railway автоматически обнаружит `Dockerfile` и `railway.json` и начнет развертывание

## 🗄️ Шаг 3: Добавление PostgreSQL базы данных

### 3.1. Создание PostgreSQL сервиса

1. В вашем проекте Railway нажмите **"+ New"**
2. Выберите **"Database"** → **"Add PostgreSQL"**
3. Railway автоматически создаст PostgreSQL сервис

### 3.2. Получение данных подключения

1. Откройте созданный PostgreSQL сервис
2. Перейдите во вкладку **"Variables"**
3. Вы увидите автоматически созданные переменные:
   - `PGHOST`
   - `PGPORT`
   - `PGDATABASE`
   - `PGUSER`
   - `PGPASSWORD`

## ⚙️ Шаг 4: Настройка переменных окружения

### 4.1. Откройте настройки приложения

1. Вернитесь к сервису приложения (не PostgreSQL)
2. Перейдите во вкладку **"Variables"**

### 4.2. Добавьте переменные базы данных

Создайте следующие переменные, используя значения из PostgreSQL сервиса:

| Переменная | Значение | Источник |
|------------|----------|----------|
| `DB_HOST` | Значение `PGHOST` | Из PostgreSQL сервиса |
| `DB_PORT` | Значение `PGPORT` | Из PostgreSQL сервиса |
| `DB_NAME` | Значение `PGDATABASE` | Из PostgreSQL сервиса |
| `DB_USER` | Значение `PGUSER` | Из PostgreSQL сервиса |
| `DB_PASSWORD` | Значение `PGPASSWORD` | Из PostgreSQL сервиса |
| `DB_SSLMODE` | `require` | Введите вручную |

**Как скопировать значения:**
1. Откройте PostgreSQL сервис → Variables
2. Скопируйте значение каждой переменной `PG*`
3. Вернитесь к приложению → Variables
4. Создайте новую переменную `DB_HOST` со скопированным значением из `PGHOST`
5. Повторите для остальных переменных

### 4.3. Добавьте другие обязательные переменные

```bash
NODE_ENV=production
PORT=3000
```

**Примечание:** Railway автоматически устанавливает переменную `PORT`, но можно указать явно.

### 4.4. Опциональные переменные (в зависимости от расширений)

Если используете расширения, добавьте соответствующие переменные:

**AWS S3 Storage:**
```bash
AWS_ACCESS_KEY_ID=your_access_key_id
AWS_SECRET_ACCESS_KEY=your_secret_access_key
AWS_REGION=us-east-1
AWS_BUCKET_NAME=your_bucket_name
```

**Azure Storage:**
```bash
AZURE_STORAGE_CONNECTION_STRING=DefaultEndpointsProtocol=https;AccountName=...
AZURE_STORAGE_CONTAINER_NAME=your_container_name
```

**Email Service - Resend:**
```bash
RESEND_API_KEY=re_xxxxxxxxxxxxx
```

**Email Service - SendGrid:**
```bash
SENDGRID_API_KEY=SG.xxxxxxxxxxxxx
```

**Google Login:**
```bash
GOOGLE_CLIENT_ID=your_google_client_id
GOOGLE_CLIENT_SECRET=your_google_client_secret
```

## 🌐 Шаг 5: Настройка домена

### 5.1. Генерация бесплатного домена

1. В настройках сервиса приложения
2. Перейдите в **"Settings"** → **"Networking"**
3. Нажмите **"Generate Domain"**
4. Railway создаст домен вида: `your-app-name.up.railway.app`

### 5.2. Настройка кастомного домена (опционально)

1. В **"Networking"** нажмите **"Custom Domain"**
2. Добавьте ваш домен
3. Следуйте инструкциям по настройке DNS

## 🚀 Шаг 6: Первый запуск

### 6.1. Проверка сборки

1. Railway автоматически начнет сборку после подключения репозитория
2. Следите за логами в реальном времени в панели Railway
3. Убедитесь, что сборка прошла успешно

### 6.2. Проверка запуска

1. После успешной сборки приложение автоматически запустится
2. Проверьте логи на наличие ошибок
3. При первом запуске приложение автоматически выполнит миграции БД

### 6.3. Проверка работы

1. Откройте сгенерированный домен
2. Убедитесь, что сайт загружается
3. Попробуйте зайти в админ-панель: `https://your-domain.up.railway.app/admin`

### 6.4. Создание администратора

После первого запуска создайте администратора через Railway CLI или через терминал:

```bash
# Через Railway CLI
railway run npm run user:create -- --name "Admin User" --email "admin@example.com" --password "your_secure_password"

# Или подключитесь к контейнеру и выполните команду
```

## 🔄 Шаг 7: Настройка автоматического развертывания

Railway автоматически развертывает при каждом push в выбранную ветку. Это включено по умолчанию.

## 🐛 Troubleshooting

### Проблема: Сборка не проходит

**Решение:**
- Проверьте логи сборки в Railway
- Убедитесь, что все файлы закоммичены
- Проверьте, что Dockerfile корректен
- Убедитесь, что `package.json` содержит все необходимые скрипты

### Проблема: Приложение не запускается

**Решение:**
- Проверьте логи приложения в Railway
- Убедитесь, что все переменные окружения установлены
- Проверьте подключение к базе данных
- Убедитесь, что порт указан правильно

### Проблема: Ошибки подключения к БД

**Решение:**
- Убедитесь, что PostgreSQL сервис запущен
- Проверьте, что все переменные `DB_*` установлены правильно
- Убедитесь, что `DB_SSLMODE=require` установлен
- Проверьте, что значения скопированы из PostgreSQL сервиса правильно

### Проблема: Медленная работа

**Решение:**
- Проверьте использование ресурсов в Railway
- Рассмотрите upgrade плана
- Оптимизируйте Dockerfile (используйте кэш слоев)
- Проверьте, что используете production сборку

### Проблема: Белый экран на фронтенде

**Решение:**
- Проверьте логи приложения
- Убедитесь, что сборка прошла успешно
- Проверьте, что все зависимости установлены
- Убедитесь, что React версия совместима (17.0.1)

## ❓ Часто задаваемые вопросы

### Можно ли использовать Netlify для фронтенда?

**Короткий ответ:** Нет, без серьезной переработки архитектуры.

**Длинный ответ:** Это SSR приложение, где React компоненты рендерятся на сервере. Netlify предназначен для статических сайтов или Serverless функций. Чтобы использовать Netlify, нужно:
1. Переписать фронтенд как статический сайт (потеряете SSR)
2. Или использовать Netlify Functions для SSR (сложно и избыточно)
3. Или использовать Netlify как прокси к Railway API (не имеет смысла)

**Рекомендация:** Используйте Railway для всего приложения - это правильный подход для SSR.

### Нужно ли несколько репозиториев?

**Нет.** Один репозиторий достаточно, так как это монолитное приложение.

### Как добавить тестовые данные?

После первого запуска выполните:
```bash
railway run npm run seed
```

Это заполнит базу данных тестовыми товарами и категориями.
